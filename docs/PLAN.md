# 星尘战棋 · 实施与验收

本轮以两份背景材料及 `UI_CHECKLIST.md` 为范围：修正棋盘交互，重做构图、角色与信息层级，完成本地双人 / AI 的可玩流程。联机协议、数据库和部署是后续工作，不把本地模式称为线上实时对战。

用户要求采用合理逻辑，不建设高成本的旧新引擎逐帧一致回放。本次保留原角色、技能与基础数值；修复错误状态边界，用针对性规则测试与实际浏览器操作验证。

| 阶段 | 实现 | 验收来源 |
|---|---|---|
| 几何与输入 | 一个格心数组，精确六角包含测试，CSS 坐标转换，DPR 独立 | `tests/hex.test.js`、浏览器逐格点击 |
| 状态与规则 | `Game` 状态模块；共享 HP/AP；无效动作拒绝；时停、冷却与地形边界 | `tests/game.test.js` |
| 布局 | 对称等宽角色舱；16:9 桌面；固定行动台；容器测量缩放 | 桌面、笔记本及窄屏截图和尺寸报告 |
| 角色 | 四张大肖像；八枚完整立姿；主／替及 P1/P2 标识；受击与移动 | 实际棋盘与素材 contact sheet |
| 行动反馈 | 图标、名称、AP/CD；可用原因；路径、伤害、地形、连携；可取消瞄准 | 浏览器战斗流程 |
| 技能演出 | 四组人物和替身插画；程序速度线、文字和时间轴；实际结算触发 | 四个技能演出截图 |
| 产品流程 | 选人、帮助、确认、认输、结算、再战、重开；AI 弹窗暂停 | 浏览器主流程 |
| 无障碍与异常 | 键盘、焦点、非单色状态、高对比、减少动画、静音、离线/加载提示 | 浏览器设置、键盘与离线回归 |
| 性能 | 静态地形缓存、纹理资源收敛、DPR 上限、条件重绘 | 帧间隔与重绘计数报告 |

实现顺序已按上述优先级落地。最终逐项状态与证据以 `UI_CHECKLIST.md` 和 `design/review/browser-report.json` 为准，不用“未发现报错”代替流程验证。

原始 HTML 只留作参考。新入口不再 fetch / eval 旧页面、不劫持 `document.getElementById`，也不会丢弃规则警告。原素材和用户截图保留；新美术与可复现处理脚本分开放置。
