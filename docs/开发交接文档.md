## 2. 核心设计（读代码前先理解这些）

- **六角战棋**，双方各 1~2 个单位；**使者与替身共享生命值**，任一单位受伤都扣同一份 HP。
- **连携距离**：使者与替身的距离上限（花京院 3 格，其余 2 格）；移动落点受此约束。
- **回合**：每回合 3 AP（卸甲期间 4 AP）；移动/普攻各 1 AP；技能按数据里的 `cost`。
- **★ CD 口径（用户 2026-09-12 正式规定，别再自行换算）**：
  `无 cd` = 每次轮到自己都能放（同一回合内仍然只放一次）；`cd 1` = 用完之后**下个自己回合放不了，隔一个回合才能放**；`cd 2` = 连跳两个自己回合。
  **落到数据里：`SKILLS[x].cd` 的值 = 用户口径的冷却回合数 + 1**。即 `cd:1` 实际等于"无冷却"（只保证同一回合不重复放），`cd:2` 才是用户说的「CD 1」。
  原因：`game.js` 的 `enterTurn()` 只在自己回合开始时把 CD 减 1，而 `skillReason()` 的判定是 `cd > 0` 就不能放。界面上那句「冷却 N 个己方回合」显示的正是数据值，语义是"还需等待 N 个己方回合"。
  本次据此把 **`armor.cd` 从 1 改成 2**（银色战车的卸甲 ⇄ 装甲：两个形态都变成真正的 CD 1 回合——用完的下个自己回合不能再切换）。`polnareff.test.js` 里已把这条语义断言出来（"下个自己回合不能切换"），反证过确实会失败。
  ⚠️ **顺带发现的口径不一致——用户 2026-09-12 明确决定「先不动，等我玩过再说」**：`blade` / `vine` 的数据值是 1（= 用户口径的"无 cd"），但技能说明里写着「CD 1回合」；`splash` 数据值 3（= CD 2）说明写「CD 3回合」；`hamon` 数据值 2（= CD 1）说明写「CD 2回合」。两种修法：**改说明文字**（不动平衡）或**改数值**（会动平衡，等于削弱剑刃/藤蔓/水花/波纹）。**没有用户的新指示，不要擅自改动这四项。**
  （2026-09-12 用户随后提过一句「剑刃不用开局就 CD」，但追问时取消了提问。实测结论：**剑刃开局并没有 CD**——开局 `s.cd` 是空的、按钮不显示 CD 徽章；放完只限当前回合，下个自己回合即恢复。所以这条是什么意图仍**未确认**，动它之前先问清楚。）
- **技能数据结构**（`SKILLS`，17 个）字段：
  `name / altName / emoji / cost / cd / range / by(user|stand|any) / passive / base / bonus / max / once / cap / pillarHp / perPillar / line / toggle / desc`
- **角色数据结构**（`FIGHTERS`，6 名）：
  `hp / def / distLimit / standDefBonus / user{name,move,range?,dmg?} / stand{...}|null / solo?`
- **单单位角色**：`stand: null` + `solo: true`（乔瑟夫）。他没有替身棋子、无连携约束、本体可普攻（`user.range/dmg`）。**这是最容易出 bug 的一类角色，见 §6 陷阱 1。**
- **事件机制**：`game.emit(type, data)` 会写 `s.log` 并回调 `main.js` 的 `onEvent`（音效、大招动画、BGM 场景切换都在那里）。
- **状态位都在 `s`（`reset()` 里初始化）**：`burn / vine / traumaCut / armorOff / swordBuff / extraAP / extraOneShot / timeReady / skipSide / fire / pillars / cd / stats …`
- **胜负**：共享 HP 归零或主动认输。
- **降级原则**：素材/音乐缺失一律**静默降级**，游戏必须仍能玩；但**新角色必须配齐 standee + portrait + cutin 三张图**，否则主界面会弹"素材未加载"警告（`artLoads` 会给每个角色请求这三张）。

  · 进度存在 **`localStorage['stardust.story']` 的 `{ cleared: [章节 id] }`**（和显示设置分开存）。**读完本章最后一页（按钮「完成本章」）才记通关＝解锁**，然后回到章节列表让玩家看到状态变化。第一章默认可进入（否则没有入口），状态从「可进入」变成「已解锁」。
  · 结算弹窗：剧情模式**打赢只留一个「继续」**（`newMatchBtn` 隐藏），点了接战斗之后的正文；输了才是「再战一场 / 返回标题」。

## 3. 界面与交互要点

- **五屏结构（2026-09-12 改版）**：`#title` 标题页 →（剧情：`#storyMenu` 章节列表 → `#storyStage` 演出）→ `#lobby` 选人页 → `#app` 战场。
  · **标题页（主菜单）**：整张背景画 + 主标题「星尘战棋」+ 副标题「命运，由你落子」+ **两个**模式选项——`01 剧情模式`（`data-title-mode="story"`）／`02 对战`（`data-mode="hotseat"`）。音量滑杆、音乐切换、玩法指南、剧情档案**都移到这一页**（这些控件有固定 id，全站只能有一份）。
    ⚠️ **2026-10-04 用户拍定：删掉单独的「人机对战」入口**——人机与否改成在选人页**逐位**决定（见下面的「逐位控制」），所以标题页只有「对战」与「剧情」两个选项。
  · **主菜单不做「默认选中」高亮**（用户要求）：平时两个选项同色，只有**鼠标悬停**（以及键盘 `:focus-visible`）才高亮。别再按 `aria-pressed` 加高亮样式——`renderDraft` 仍会同步 `aria-pressed`，那只是给读屏用的语义。
  · **剧情章节列表**：`#storyMenu`，`renderStoryMenu(storyRoadmap(), { cleared })` 渲染；已解锁的是按钮（带 `data-story-chapter="章节下标"`，点了直接跳进那一章），未解锁的是灰掉的 `<div>`（只显示编号 + 标题 + 话数 + 「未解锁」标签）。
  · **剧情演出页**：`#storyStage`，按 `STORY_CHAPTERS[i].scenes` 一幕一幕播正文；右侧「本关规则」列出本关的角色改动；按钮文字由 `storySceneAt()` 给出（继续 / 开始对决 / 完成本章）。战斗结束后回到剧情继续演后续正文。渲染函数是 `hud.js` 的 `renderStoryStage(chapter, view)`，场景解析是 `story.js` 的 `storySceneAt(chapter, index)`。
  · **选人页**：六角色卡片（`renderDraft`）；顶栏只剩「返回标题」（`#backToTitle`）与指南/档案入口。原来的 `.lobby-heading` 与 `.mode-picker` 已删除。
  · **★★ 逐位控制（2026-10-04 用户拍定的设计，「人机对战」与「双人同屏」合成同一个模式）**：
    · **每个角色位自己决定是真人还是人机**——大厅里每一位的选人面板**上方**有一颗「真人 / 人机」开关
      （`data-control-slot="p1|p2|p1b|p2b"` + `data-control="human|ai"`，由 `hud.js` 的 `controlSwitch()` 渲染、`main.js` 的点击分支写入 `draft.control`）。
      1v1 两个开关，2v2 四个。默认＝用户拍定的那一套：**P1① / P1② 真人、P2① / P2② 人机**。
    · **引擎里的唯一口径是 `s.control`**（`{ p1: 'human' | 'ai', … }`，只有参战槽位有键），
      由 `game.setRoster({ p1b, p2b, control })` 在 `start()` 之前登记（`start()` 的签名与调用写法被测试钉住了，不许加第 5 个参数）。
      判断"这个位子该不该自动行动"只准用 `game.isAI(槽位)` / `controlOf()` / `hasAI()` / `allAI()`——
      **不要再写 `s.mode === 'ai' && teamOf(slot) === 'p2'` 那种按整方判断的老写法**（2v2 与混合位子下会错一半，
      `main.js` 的 `humanTurn()`、`hud.js` 的 `waiting` / `COMPUTER` 标签、`COMPUTER TURN` 文案、认输按钮都改读了控制表）。
    · **`s.mode` 只是兼容字段**：含义变成"这一局里有没有 AI 位"（有人机就是 `'ai'`，全真人就是 `'hotseat'`）。
      不登记控制表时按老口径兜底：`mode === 'ai'` ＝ P2 侧人机、P1 侧真人，所以旧调用点（含全部剧情章节）行为一字不变。
    · **剧情模式忽略控制表**：永远是"玩家真人 / 敌方人机"。**人机与 2v2 可以同时开**（AI 只打它自己那一个角色，
      `ai.js` 按 `u.slot === s.turn` 取自己的棋子、按 `u.side !== teamOf(s.turn)` 找敌人）。四个位子全人机＝**观战**（挂着看两边自己打完）。
    · **认输只对真人位开放**：轮到人机位时 `#resignBtn` 禁用（`renderActions` 里按 `waiting` 关掉；打开菜单时 `main.js` 再刷一次），处理函数里还有一道 `if (!humanTurn()) return;`。
    · **网址参数**：`?mode=ai`（＝P2 侧人机）、`?v2v=1`、`?vs=a,b,c,d` 照旧；**新增 `?ai=p1b,p2`**——列到的位子是人机、其余参战位子都是真人，`?ai=`（空串）＝ 全真人，方便手动验证混合局面。解析在 `hud.js` 的 `applyAiParam()`（纯函数，有测试）。
  · 流程函数在 `main.js`：`showScreen(id)` 统一管五屏的 `hidden`，另有 `showTitle()` / `showStoryMenu()` / `showStoryStage()` / `showLobby()` / `startStoryMatch()` / `startMatch()` / `returnToDraft()`。
  · **背景画为什么用 HTML `<img>` 而不是 CSS `url()`**：单文件版会把 CSS 内联到根目录的 HTML，CSS 里的相对路径（`../../assets/...`）会指向项目外而失效；`<img src="assets/out/lobby/...">` 在开发版与单文件版都成立。**改背景时不要搬回 CSS。**
  · 背景素材：`assets/out/lobby/title-bg.webp`（1536×1024，109 KB）；原图母版 `assets/src/lobby/title-bg.png`；提示词 `design/prompts/title-bg.txt`；新增工具 `tools/prepare_scene.mjs`（场景图 PNG→WebP，不抠图）。
  · 背景构图（**v2 = 对峙构图**，2026-09-12 二次修改）：DIO 站在楼梯上方的高台、一手叉腰、**俯视蔑视**下方；承太郎、乔瑟夫、波鲁纳雷夫、花京院、伊奇、阿布德尔**聚拢在楼梯下方、全部转身朝上看向 DIO**，双方之间隔着一整段空台阶；左侧留大片暗区给标题与按钮。波鲁纳雷夫穿**黑色无袖高领上衣**（不是白夹克）。
  · 背景素材沿革：`assets/src/lobby/title-bg.png`（v1，原「一字排开」构图）与 `title-bg-v2.png`（v2 对峙构图，**线上 `assets/out/lobby/title-bg.webp` 用的是 v2**）；提示词 `design/prompts/title-bg.txt` 与 `title-bg-v2.txt`。v2 是用 `image_gen.py edit --image <v1>` 定向修改的——**改图时必须在提示词里逐条列出「必须保持不变」的项**（人数、每张脸与发型、背景建筑、画风、左侧留空），否则人物身份和画风会跟着一起跑掉。

- 音量滑杆 + 音乐切换（`#volumeRange` / `#musicBtn` / `#musicState`）、**玩法指南**（`#helpDialog`，只讲基础、不含角色专条）、**剧情档案**（`#storyDialog`）。

## 6. ★ 必须知道的陷阱（都是真实踩过的）

1. **单单位角色会让"没有替身"的代码崩掉整帧/整块 UI**
   症状极隐蔽：*选中某角色后其他立绘消失*、*放完技能行动点不刷新*。
   已修三处（`render.js` 连携虚线、`position()` 空值、`hud.js` 悬停预览与行动台摘要）。
   **新增单单位角色时，全项目搜 `.stand`、`partner(`、`pairDistance(`、`distLimit(`**，逐个加守卫。
   **一句话记住**：任何"取替身名 / 取替身立绘 / 算连携距离"的地方，都必须先判断这个角色有没有替身。
2. **一帧内的异常会让这一帧/这块 UI 静默不更新** ❗
   所以渲染类改动必须配**假上下文/假 DOM 测试**（照抄 `render.test.js` / `hud.test.js` 的模板：Proxy 假 Canvas、最小假 DOM）。
   写测试时要**反证**：临时去掉守卫跑一次，确认测试真的会失败（否则只是"看着像在保护"）。

    （实测 rgb≈(45,32,86)、蓝度只有 **28–45**）→ 裤子被判成"背景边缘"，扣成半透明、又被"去蓝边"
